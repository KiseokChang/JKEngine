### Task 1: 서버 notes_read/notes_write + state/notes.json

**Files:** `engine/include/server/JKWindowServer.h`(없음 — 멤버 불필요),
`engine/src/server/JKWindowServer.cpp`

- static 헬퍼(WriteSettingsKv 뒤): NotesPath()(StateDir()+"\\notes.json"),
  LoadNotes(문자열 전체 읽기→AgentJson), WriteNotesFile(json text — .bak 1세대,
  256KiB 캡).
- kPermMatrix: `{"notes_read","none","allow"},{"notes_write","none","allow"}`.
- 디스패치: `notes_read` → 전체 반환(파일 없으면 빈 배열, 정상).
  `notes_write` → op 화이트리스트(add_note/add_item/move_item/del) + 검증
  (text 1..512, title 1..128, state 0..2, id>0) + RMW + 응답.
  - RMW: ReadNotes → AgentJson 배열 조작 → WriteNotesFile. AgentJson 재직렬화
    대신 **원문 수술 회피** — notes.json은 서버가 유일 쓰기자이므로 간단한
    수동 JSON 빌더로 전체 재직렬화한다(ts는 epoch ms로 읽어 그대로 사용 —
    int64라 AgentJson으로 못 읽으므로 **행 단위 원문 파싱**(memchr 행 스캔,
    PruneReceipts 선례)으로 id/text/win/state/ts/src를 뽑고 다시 snprintf.
    단순화: **행 객체를 원문 문자열로 보관**(행 파싱 대신 '{...}' 경계 스캔,
    TrustRecordText 선례) → add/move/del은 행 문자열 편집.
  - move_item: 행 원문에서 `"state":N` 스칼라 치환(고정 필드라 안전).
  - add: `,"id":N,"text":...,"win":0,"ts":<ms>,"src":"agent|user"}`.
  - 에이전트 add_note 성공 시 agent.notify 방송:
    `PushAgentEventJson` `{"topic":"agent.notify","data":{"title":"[노트]",
    "body":<text>},"ts":<ms>}` (§2.4 — user 추가는 방송 없음).
- Init에 로드 없음(도구가 파일을 매번 읽음 — 런타임 미러 불필요).

**검증:** agentctl로 read/add/move/del 실측.
