### Task 1: 서버 files_list/files_read/files_audit + 게이트 + 파킹

**Files:** `engine/src/server/JKWindowServer.cpp`

- kPermMatrix: `{"files_list","server(files)","none"}`,
  `{"files_read","server(files)","none"}`, `{"files_audit","none","allow"}`
  + agent_permissions 분기: gate "server(files)" 처리(파일값 그대로 표시).
- `FilesPermRaw(tool)` 헬퍼 — permissions.json 원문값("missing"/"allow"/
  "ask"/"deny"; WritePermissionsEntry 선례의 exe-dir 인라인, windows.h
  TU 금지).
- 경로 검증기 `ValidFilePath(path)` — 절대 드라이브 형식 + UNC/상대/`..`
  거부 + ≤260.
- `AgentToolAllowed`: askCapable += files_list/files_read.
- 디스패치 3분기(read_receipts 뒤, launch_chat 앞):
  - `files_list`: gate Deny → permission_denied; control-only && 값!=allow →
    파킹(kind "files_access", close_window 선례 — pendingApprovals_ +
    approval_request 방송, title=path); 성공 → 엔트리 배열(dir 우선, 512 캡).
  - `files_read`: 동일 게이트; 64KiB 캡 + NUL 스니핑(첫 4KiB) → binary.
  - `files_audit`: none/allow; receipts 꼬리 256KiB 행 스캔에서 files_*
    행 → {ts(sec),tool,ok,path} (AgentJson 행 파싱, 상한 limit 기본 50).
- 파킹 해소: 승인 시 원본 요청 재실행(allow) — pendingApprovals_ 해소 경로
  는 close_window 선례를 그대로 복용하는데, 파일은 승인 시 **재실행**이
  필요하므로 파킹 구조체에 요청 인자 보관 필요성을 1차 확인하고 최소 변경.

**검증:** agentctl 실측 — list/read/audit + 에이전트 ask → 승인 큐.
