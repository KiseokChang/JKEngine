# jkbridge (폰 브라우저 웹 게이트웨이) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PC에서 도는 jkbridge.exe(HTTP+WebSocket 게이트웨이)를 통해 안드로이드 폰 브라우저에서 jkchat 전 기능(LLM 채팅+슬래시+승인)을 쓰게 한다.

**Architecture:** 폰 브라우저 ↔ WS ↔ jkbridge(범용 도구 릴레이) ↔ named pipe ↔ jkwinserver. LLM은 jkchat에서 추출한 JKLlmEngine 공용 모듈(claude CLI 스폰+stream-json+resume)이 브리지에서 스폰. 승인 파이프라인은 서버 수정 없이 기존 그대로.

**Tech Stack:** C++17, Winsock2(TCP/HTTP/WS 수기), Win32(named pipe+CreateProcess), 단일 HTML/JS 웹 UI(exe 임베디드).

**Spec:** `docs/superpowers/specs/2026-09-18-jkbridge-design.md`

## Global Constraints

- 포트 기본 8790 / 토큰: `state/jkbridge.json` {token,port}, 첫 실행 CSPRNG 32-hex 생성.
- WS 프레임 상한 1MiB, 텍스트 프레임만, 동시 세션 상한 4, 토큰 실패 레이트리밋 IP당 10회/60초.
- WS 프로토콜 = 범용 4종(chat/tool/approve/hello) + 6종(hello/stream/chat_done/reply/event/error) — 채팅 특화 프레임 금지.
- 승인 문구는 kind별 전용 라벨(opus MAJOR-1 계승) — close_window 재용 금지.
- 서버(jkwinserver) 코드 수정 금지 — 승인 파이프라인 무수정.
- 프로브는 stub 엔진 + 임시 디렉터 실행(chat.json 오염 방지 — docs/54 레슨⑥), `> log 2>&1` 리다이렉트(docs/54 레슨④), ×2 연속 ALL PASS.
- 빌드: `engine/build_with_temp.sh`(기존 관례) — jkchat은 MinGW(-municode -static).
