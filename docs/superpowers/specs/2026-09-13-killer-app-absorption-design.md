# 킬러 앱 흡수 전략 — Phase A: TUI 에디터/파일 매니저

- 날짜: 2026-09-13
- 상태: 승인 (브레인스토밍 합의)
- 선행: docs/43 (engine/desktop split P1), docs/40~42 (터미널 선택/IME, 마우스, 리플로우)

## 1. 문제와 목표

브라우저(OSR)와 동영상 플레이어만으로는 JKENGINE 위에서 하루를 보낼 수 없다.
멀쩡한(성숙한) 오픈소스 앱을 흡수해 매일 사용하면서, 사용 중 발견한 지점에
본인 아이디어를 개조로 녹인다. 그 과정의 실측 데이터가 P4 SDK 계약 설계의 입력이 된다.

**최종 목표**: 윈도우를 쓰지 않고 JKENGINE 환경만으로 일상이 돌게 만든다.
그러므로 완성도보다 빠른 구축이 우선이다 — 경험을 빨리 쌓아야 고칠 게 보인다.

## 2. 전략 (3경로, 단계 전환)

| 경로 | 내용 | 채택 |
|---|---|---|
| A | TUI 앱 흡수 — 터미널 클라이언트 위에서 확보 | **지금** |
| C | 코드 포크 → jkclient 네이티브 포팅 | A 사용 중 갭이 보이면 부분 승격 |
| B | OSR/Electron 통째 호스팅 | 최후 수단 (거대 GUI 앱 전용) |

근거: 터미널 인프라(docs/40~42)가 이미 완성되어 있어 TUI 앱은 오늘 바로 돈다.
코드베이스가 작아 개조(아이디어 녹이기)가 쉽고, 흡수 경험 자체가 P4 SDK 계약의
요구사항을 도출한다.

## 3. 성공 기준

1. 에디터 + 파일 매니저가 JKENGINE 터미널 위에서 일상 사용에 충분
2. 최소 1개 앱에 개조(아이디어 녹이기) 커밋 1개 이상
3. 흡수 과정의 막힌 지점(창 모델, 입력, 클립보드, 경로, 프로세스 접근)이
   기록되어 P4 SDK 계약 문서의 요구사항 목록이 될 것

## 4. 비목표 (YAGNI)

- GUI 앱 OSR 호스팅(B) — 지금 하지 않는다
- 대규모 네이티브 포팅(C) — 지금 하지 않는다
- 터미널 앱 자체 개발 — 흡수만 한다

## 5. Phase A 설계

### 5.1 앱 선정

- **파일 매니저: `lf`** (Go, 단일 바이너리, 마우스 지원, 셸 연동).
  `ranger`(Python)보다 가볍고 포크 개조가 쉬움.
- **에디터: `helix`** (Rust, LSP 내장, 모던).
  대안 `micro`(Go + Lua 플러그인) — 개조 난이도는 더 낮음. helix가 일상에
  안 맞으면 교체 후보.

### 5.2 실행 방식

기존 ConPTY 터미널 클라이언트 위에서 실행. 확보된 것(docs/40~42)으로
클립보드/IME, 마우스 SGR, 리플로우가 이미 동작하므로 신규 작업은 얇게:

1. **런처 등록** — launcher에 lf/helix 엔트리, 기본 작업 디렉토리 지정
2. **연결 고리** — lf에서 파일 열기 → helix 실행, 폴더에서 셸 열기
3. **개조 지점** — lf 커스텀 명령 → 엔진 스크립트(.jkx) / jkagentd 도구 호출.
   예: 파일 선택 → 에이전트에 "이거 정리해줘" 전달.
   helix는 LSP/외부 명령 경로로 엔진과 연결.

### 5.3 구축 순서

빠른 것부터, 파일 매니저 체감이 더 크므로 lf 우선:

1. lf 확보 + 실행 확인
2. launcher 등록
3. helix 확보 + 실행 확인
4. lf → helix 파일 열기 연결
5. 개조 실험 (lf 커스텀 명령 → 에이전트)

## 6. A→C 전환 트리거 (C 후보 적립)

lf/helix를 쓰다가 다음 징후가 보이면 그 부분만 포크 포팅(C)으로 승격한다:

- 터미널 촉감으로 불가능한 것 — 파일 아이콘/썸네일, 창 분리, GUI 다이얼로그
- 개조가 앱 코드 깊숙이 들어가야 하는 것

기록 방법: 실행 문서(docs/44, 가칭)에 **"C 후보 적립"** 섹션을 유지한다.
감이 아니라 증거 기반으로 승격한다.

## 7. P4 SDK 피드백

흡수 과정의 막힌 지점을 실시간 기록한다 (별도 작업 없이 Phase A 진행 중 메모):

- 창 모델 갭 (터미널 한 창에 앱이 갇힘)
- 입력/IME 갭
- 클립보드/경로/프로세스 접근 갭

이 목록이 P4(앱 engine 밖 SDK 계약화) 설계의 요구사항 입력이 된다.
