# vplayer 부드러운 스크럽 + 역방향 재생 재설계 (스펙 초안, 2026-09-24)

상태: **구현 완료 (docs/50 §12 참조, 2026-09-24)**

## 1. 왜 이것인가 (사용자 보고, 2026-09-24)

현재 조그(docs/50 §8)·역방향 자동 재생(docs/50 §10)이 사용자가 원하는 동작이 아니다:

- 조그 = "프레임 단위 이동" 느낌 — 다이얼이 위치 지정자라 돌릴 때 프레임이 점프로 찍힌다.
- 링(10s) 밖은 키프레임 시크 폴백 → 착지 점프 → 디코드 크리프. 특히 뒤로 갈 때 답답.
- 역방향 자동 재생(v2 역케이던스)도 스텝 체감 + 소진 시 키프레임 시크 점프로 "어색".

**사용자 확정 답변**:
1. UX 모델 = **위치 추적 스크럽** — 드래그한 시간 위치로 화면이 연속적으로 흐르며
   따라감 (유튜브 시크바 감각). 셔틀(속도) 모델 아님.
2. 부드러운 역방향 범위 = **~16초** (버퍼 캡 한도, 1080p 기준).
3. 스크럽 중 오디오 무음 OK.
4. 메모리 여유 OK ("메 좀 써도 됨").

## 2. 핵심 발상

역방향은 "재생"이 아니라 **GOP 단위 전진 디코드 버퍼의 역순 표시**다.

- 지금 jogRing은 디코드 프레임의 접미사 링(10s/1.5GB) — 역방향 표시 재료는 이미 있으나
  (a) 10s 캡, (b) 링 밖 즉시 키프레임 시크, (c) 표시가 target 위치 직찍이라 흐름이 없다.
- GOP 체인: 현재 위치 뒤로 GOP(~2s) 단위로 통째로 디코드해 보유 → 범위 안 역방향은
  디코드 0으로 프레임당 1장, 진짜 재생처럼 흐른다. 소진 직전엔 백그라운드가 다음
  체인 GOP를 선제 디코드 (화면은 기존 버퍼로 계속 흐르므로 끊김 없음).

## 3. 설계

### 3.1 스크럽 윈도우 버퍼 (jogRing 확장)

- `scrubWin`: 현재 스크럽 앵커 뒤로 GOP 체인을 연결해 놓은 프레임 버퍼
  (연속 pts 구간 [lo, anchor]). jogRing을 대체하되 push-trim 구조와 락 도메인(videoQ와
  같은 m)은 계승. 캡: `kJogRingMaxSecs = 16.0` / 바이트 캡 6GB
  (사용자 승인 2026-09-24; 4K NV12 12.4MB×30fps 기준 16s 전체 스팬 — §5 참조).
- 체인 리필: 표시 위치가 `lo + kRefillAhead`에 도달하면 워커가 직전 GOP 키프레임부터
  전진 디코드해 앞에 붙인다 (seek stage (a)와 같은 경로, vSeekSeq 세대 보호 재사용).
- 정방향도 같은 버퍼: 앵커 앞은 기존 디코드 크리프 게이트가 버퍼로 흘려보낸다.

### 3.2 위치 추적 스크럽 (신설 표시 시계)

- 드래그 = target pts T(t). UI 펌프가 매 프레임 표시 시계 D를 T쪽으로 흐르게 전진:
  `D += clamp(T − D, −kFlowStep, +kFlowStep)`, `kFlowStep = kFlowMax / fps` 프레임
  (kFlowMax = 8× 정도 — 실측으로 튜닝). D가 T에 도달하면 대기(추적 완료).
- D가 움직일 때마다 버퍼/디코드 경로에서 D에 대응하는 프레임을 표시 — "사진 넘기기"가
  아니라 연속 흐름. 전진·후진 동일 기계 (후진은 체인 버퍼 역순, 전진은 디코드 크리프).
- 다이얼(노브)과 시크바 드래그 둘 다 target 공급자로 통일 — 렌더러는 target만 본다.

### 3.3 릴리스 시맨틱 (기존 유지)

- 놓으면 기존 `finishScrub` 경로 그대로: 정밀 시크 착지 + 드래그 전 재생 상태 복원.
  (vpt9 S4 계약 불변 — "그 위치에서 정지"는 표시가 정지한다는 뜻, 재생 재개 여부는
  기존 계약 유지가 정답: 재생 중에 드래그했으면 재생 재개.)

### 3.4 역방향 자동 재생(v2) = 같은 기계 위에서 소각

- 역케이던스 전용 기계를 폐기하고, 스크럽 시계의 자동 모드로 통합:
  D를 −1× 프레임 속도로 전진 (체인 버퍼 역순), 체인 리필이 계속 뒤를 채움.
  버퍼 소진 대기 중 화면 유지 (프리즈 후 점프 없음 — 리필 착지 시 재개).
- 이러면 "역방향 재생"과 "역방향 스크럽"이 자원·기계를 공유 — 유지보수 단일 진실원.

### 3.5 기존 결함 방어 계승 (docs/50 §8.1·§10 레슨 전부 유지)

- vSeekSeq 세대 카운터: 체인 리필 시크에도 동일 적용 (stage (a) bump → 게이트 폐기).
- audioSkipBelow: 시크 Ok 경로 target 아래 오디오 폐기 유지.
- 폴백 웨지 교훈: 홀드 루프 탈출은 wantSeek만이 아님 — 체인 리필도 탈출 조건에 합류.
- EOF 클램프 롱 전진 조그 시나리오: 체인 리필이 파일 시작에서 소진되면 D 클램프(0).

## 4. 검증 계획

- **vpt13 (신설)**: 위치 추적 흐름 게이트 — 드래그 중 표시 pts를 시간 샘플링해
  (a) 단조 연속 진행(한 샘플 점프 ≤ kFlowMax×1프레임+여유), (b) 역방향 드래그에서
  키프레임 점프 0, (c) 릴리스 정밀 착지+재생 복원. vpt2_test.mp4(번인 카운터 직독) +
  합성 1080p(tmp/test_media/vpt_hires.mp4) 이원화.
- 회귀: vpt9(조그 스크럽)·vpt4(재생 e2e)·vpt5(게이트)·vpt11(역방향) 전부 —
  vpt11은 역방향 기계 교체의 직접 피해자라 기대값 갱신(스텝 카운트 판정 → 흐름 판정).
- 클린 바이너리 공식런 2연속 원칙 유지.

## 5. 위험

- 조그/시크/게이트 영역은 문서화된 레이스 다발(vSeekSeq·audioSkipBelow·gate hold) —
  변경은 전부 "기존 계승 + 단일 신설(체인 리필)"로 절제.
- 4K에서 16s 버퍼 = 4K NV12 12.4MB × 30fps × 16s ≈ 5.9GB — **바이트 캡 6GB**
  (사용자 승인 2026-09-24, 커밋 3fc288e — 1.5GB에서 상향)로 4K도 16s 전체 스팬을
  담는다. 캡이 secs 16s보다 먼저 바인드하는 것은 8K급에서만이다(해상도별 유효
  범위는 캡이 정하며 secs 16s는 상한). 체인 소진 대기 UX는 "정지 후 재개"로 일관.
- 디코드 스레드 경합: 리필 디코드가 정방향 재생 디코드와 워커를 공유 — 리필은
  스크럽/역방향 세션 중에만 활성 (일반 재생 중엔 체인 유지 불요, 기존 동작 무변경).
