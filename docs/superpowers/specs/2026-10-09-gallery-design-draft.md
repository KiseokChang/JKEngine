## 기존 원문 (갤러리와 겹치는 것)

- **shot 앱**(docs/35 T4, 모듈 `shot`/"Screenshots" 480x420):
  `<exeDir>\state\screenshots\*.png` 최신순 리스트 + 선택 1장 디코드
  표시(LoadImageFile). 확대/회전/삭제 없음.
- 기타 이미지 경로: snapshot/pcx 모듈(구 포먼), iconedit(자체 편집).
- 폰의 사진 원천: `/sdcard/` 저장소(Termux에서 권한이 있으면 접근 가능) —
  카메라·받은 파일·스크린샷이 모두 있으나 엔진은 현재 screens dir만 봄.

## 후보 설계 (추천 1순위 — A안)

**A안(추천): 신규 `gallery` 모듈 — "hub" 성격으로 shot과 스코프 분리**
- 썸네일 격자(최신순) + 선택 1장 전체 보기(이전/다음 이동) + 디렉터리 탭.
- 소스 디렉터리: state/screenshots(shot과 공유·읽기 전용) + 사용자 지정
  폴더(settings.json `gallery.dirs` — 복수 경로 리스트, 폰에서는
  /sdcard/Pictures 등을 폰 settings에 직접 기록해서 켠다).
- 썸네일: LoadImageFile 축소 1회 스캔 + 디스크 캐시(state/gallery/thumbs,
  파일명 해시 키) — 재부팅 재조명 방지.
- 스폰: 기존 모듈 registry(JKAppModule_*) + 런처 등록 — .jkx MODL 스캔
  선례(docs/77 §7)와 무관한 기본 내장 모듈로.
- 보기 화면: 핏 표시(픽셀 정합 — fit-scale 함정 원장 존중), 이전/다음
  키보드+버튼, 파일명·크기 표시. 삭제/회전은 범위 밖(v1 YAGNI).

**B안(대안): 기존 shot 앱 확장** — 썸네일 격자+복수 폴더를 shot에 이식.
- 장점: 모듈 수 증가 없음. 단점: shot은 "스크린샷 뷰어"로 소속 명확한데
  허브 성격을 얹으면 단일 책임이 흔들린다 + 폰 캡처 원천(shot이 쓰는
  shot_<ts> 파밍 계약)과 사진 원천의 성격이 다른데 섞인다.
