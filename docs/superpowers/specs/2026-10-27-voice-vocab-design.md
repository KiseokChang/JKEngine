## 목적

LLM 없이(오프라인 즉발) 조작 가능한 구두 어휘를 늘린다 — 정확매치 즉발+
stub 폴백 구조(산업 표준 — 리서치 §4)의 **어휘 표 커버리지 확장**.

## 재량 결정 원장 (기각 시 즉시 수리)

- **D1 어휘=무인자 우선**: 즉발 경로는 무인자 명령만(+앱명 인자 — 기존
  Launch 앱명 패턴 원존). 인자 필요 조작("오른쪽으로 100 옮겨줘")은 LLM
  턴 소관 — 신규 파서 금지("STT 텍스트==타이핑 텍스트"·ChatLlmActionParse
  원존 불변).
- **D2 도메인 순서 (리서치 권장)**: ①재생(vplayer·music ②알림 ③파일) —
  v1 배치 = **재생+알림**(기존 도구 접점이 이미 있는 것)·파일/갤러리 =
  차기.
- **D3 접점 실측 우선**: ChatRouter가 매핑 가능한 기존 도구만 연결 —
  도구 부재 액션(예: vplayer play/pause 도구)이 없으면 **해당 어휘는
  배제+원장행**(stub 안내 유지 — 도구 신설 라인 분리 — v2 후보).
- **D4 프롬프트 힌트 갱신**: kVoicePrompt도 같이 확장(어휘 원문 일치 —
  #112 EYESfix 원존).
- **D5 계보**: selftest **2y** 신설(어휘 표 → ChatAction 매핑 원문 등호).
- **D6 캐논 승계**(4축 등호)·폰 주소 미인쇄·커밋 계약 원존.

## 1. 배치 설계

- ChatRouter kRouteTable/kAliasTable에 신설 어휘(한국어 — 원문만):
  - 재생: "재생해줘/멈춰줘/정지해줘/다음 곡/이전 곡" — 대상 = vplayer
    재생 도구(접점 실측 — 도구 부재 시 원장행).
  - 알림: "알림 뭐 왔어/알림 보여줘" — notify 도구.
- 어휘 중복/이중 해석(정확매치↔별명) 계약 원존 — 표 한 행 1의미.
- stub 안내문 원존(미매치 발화의 정직 표기).

## 2. 테스트·게이트

- 2y: 어휘별 ChatAction 등호(신설 어휘 N건+기존 회귀 0)·이중 해석(별명
  우선순위)·무인자 강제.
- WSL probe: 발화→동작 원문(즉발·기존 legs 회귀 0)+폰 동형(접촉 런).
- EYES: 폰에서 신설 어휘 발화 체감(PENDING).
