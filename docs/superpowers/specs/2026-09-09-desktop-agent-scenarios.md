# jkdesktop AI 에이전트 — 시나리오 카탈로그

- 날짜: 2026-09-09 (Round 1 다양화 — 시나리오 50 → 92개)
- 성격: 브레인스토밍 결과물. 구현 설계는 별도 문서:
  `2026-09-09-desktop-agent-platform-design.md`
- 목적: "에이전트가 jkdesktop에서 **무엇을 할 수 있는가**"의 전체 지도.
  각 시나리오는 필요한 능력을 태그로 표기한다.

**능력 태그**: `[보다]`=구조화 상태/이벤트 읽기, `[만지다]`=창/앱 조작,
`[실행]`=앱 실행·터미널, `[캡처]`=창 픽셀 캡처, `[기억]`=이벤트/receipt 히스토리,
`[협업]`=에이전트 간 통신, `[모델]`=LLM 추론 필요

## A. 사용자 일상 — "데스크탑이 나를 위해 일한다"

- **A1 말로 조작** `[만지다][실행][모델]`
  "터미널이랑 브라우저 나란히 띄워줘" → 앱 실행 + 레이아웃 배치. 실행 전
  미리보기 오버레이로 확인, 되돌리기 칩 제공.
- **A2 업무 모드 저장/복원** `[보다][만지다][기억]`
  현재 창 배치를 "작업"·"영상" 등 이름으로 저장. 아침에 어제 상태 그대로 복귀.
- **A3 반복 패턴 → 자동화 승격** `[기억][모델]`
  같은 동작 3회 반복 감지 → "버튼으로 만들어드릴까요?" → 태스크바 단축 버튼 승격.
- **A4 포커스 문맥 질의** `[보다][모델]`
  포커스된 터미널의 에러 해석, 브라우저 페이지 요약, 열린 문서 질의응답.
  짧은 답은 팔레트에, 긴 답은 에이전트 패널 창으로.
- **A5 알림 트리아지** `[보다][모델]`
  흩어진 알림을 모아 중요도 순 요약. "중요한 건 2개예요".
- **A6 예약/트리거** `[보다][실행]`
  "빌드 끝나면 알려줘", "30분 뒤에 회의 알림" — 이벤트 구독 + 타이머.
- **A7 접근성 비서** `[보다][캡처][모델]`
  화면 읽어주기, UI 요소 설명, 음성 완전 조작. 커스텀 데스크탑이므로
  접근성 API부터 넣을 수 있는 OS급 기능.
- **A8 통합 검색** `[보다][기억][모델]`
  "어제 그 PDF 창 어디 있지?" — 창·파일·터미널 출력·영상 장면 통합 검색.
- **A9 자리 비움 정리** `[보다][만지다]`
  user_idle 감지 → 레이아웃 저장 + 민감 창 최소화 + 잠금 제안.
- **A10 창 청소부** `[보다][만지다]`
  오래 포커스 안 받은 창 목록 → 개별 [닫기] 승인 후 정리.
- **A11 세션 완전 복원** `[기억][만지다]`
  레이아웃을 넘어서 세션을 복원 — 터미널 cwd·실행중이던 명령, vplayer 재생
  위치, 브라우저 탭, 편집 중인 문서. "레이아웃 복원"과 "세션 복원"은 다른 깊이.
- **A12 손 없는 조작** `[보다][모델]`
  손이 바쁠 때 음성으로 — "다음 트랙", "일시정지", "이 창 저장해줘".
  vplayer·터미널 조작이 목소리로 끝남.
- **A13 스케치 → 레이아웃** `[캡처][모델]`
  손으로 그린 배치 스케치(사진)를 보여주면 실제 창 배치로 변환.
  "이렇게 놔줘"의 물리적 버전.
- **A14 방해 금지 모드** `[보다][만지다]`
  집중 세션 시작 → 알림 억제 + 불필요 창 최소화 + 타이머. 종료 시 원상복구.
- **A15 시간대 데스크탑** `[보다][기억][모델]`
  아침엔 밝은 테마+업무 레이아웃, 저녁엔 어두운 테마+영상 모드 — 시간대별
  전환을 사용 패턴에서 학습해 제안.
- **A16 창 별명** `[보다][기억]`
  "이 창을 '계획서'라고 부를게" → 이후 "계획서 찾아줘", "계획서 내려놔"처럼
  이름으로 창을 조작. 에이전트의 별명 사전은 사용자마다 다름.
- **A17 클립보드 비서** `[기억][모델]`
  복사 히스토리 보관 + 스마트 변환 — "URL 깔끔하게 붙여줘", "표로 붙여줘",
  "30분 전에 복사한 그 경로".
- **A18 첫 앱 온보딩** `[모델]`
  새 .jkx 설치 직후 에이전트가 사용법 요약 + "3일 쓰고 효율 팁을 드릴게요".
- **A19 손님 모드** `[보다][만지다]`
  게스트가 잠시 쓸 때 — 특정 앱만 허용, 에이전트 기록/타임라인에 남기지 않음.
- **A20 긴급 상황 대응** `[보다][실행]`
  배터리 부족·네트워크 끊김 감지 → 열린 작업 상태 저장 → 안전 모드 전환 안내.

## B. 개발자 동료 — "동료가 하나 더 생긴다"

- **B1 테스트 러너** `[실행][보다]`
  빌드 → 실행 → probes 스모크 → 로그 판독 → 통과/실패 리포트 자율 수행.
- **B2 크래시 수사관** `[보다][기억][모델]`
  크래시 발생 시 관련 로그·직전 이벤트를 수집해 "원인 3줄 요약" 리포트.
- **B3 로그 회귀 탐지** `[보다][기억]`
  빌드 간 로그 diff에서 새로 생긴 warning/에러 패턴만 추려 보고.
- **B4 앱 공장** `[실행][만지다][모델]`
  "2048 변형 하나 만들어줘" → .jkx 생성 → 자기가 실행·검증까지.
- **B5 리팩터링 감시자** `[보다][실행]`
  3-lib 분할 작업 중 의존성 방향 위반·빌드 깨짐을 상시 감시·보고.
- **B6 문서 관리인** `[보다][모델]`
  코드 변경 감지 → docs/*.md 해당 섹션 갱신 제안 (마진 코멘트로).
- **B7 버그 재현 담당** `[기억][실행]`
  버그 보고 시 이벤트 히스토리에서 조작 순서를 재현해 확인.
- **B8 성능 코치** `[보다][기억][모델]`
  프레임 드랍 패턴 분석 → "OSR 창 3개 떠있을 때만 발생하네요".
- **B9 스펙-코드 대조관** `[보다][모델]`
  docs의 명세와 실제 동작의 불일치 탐지 — "문서엔 32개 슬롯이라는데 실측은
  31개입니다" 같은 증거 기반 보고.
- **B10 마이그레이션 조수** `[실행][모델]`
  3-lib 분할 같은 대형 리팩터링의 기계적 부분 수행 — 파일 이동 목록,
  빌드 깨짐 순서대로 수리, 커밋 단위 검증.
- **B11 벤치마커** `[실행][기억]`
  빌드마다 프레임 타임·메모리·부팅 시간 자동 측정 → 회귀 시 경보.
  성능 기준선이 기록으로 남음.
- **B12 크로스앱 시나리오 테스트** `[실행][보다]`
  "vplayer 열고 → 30초 seek → 일시정지 → 종료" 같은 E2E 시나리오를
  스크립트로 재생·검증 — 스모크의 상위 계층.
- **B13 개발 튜터** `[기억][모델]`
  "이 버그 왜 이렇게 고쳤지?" → git 히스토리 + 당시 로그를 묶어 설명.
  과거의 자신에게 물어볼 수 있게 됨.
- **B14 커밋 검문관** `[보다][기억]`
  커밋 전 diff가 과거 교훈(레슨 목록)을 위반하지 않는지 체크 —
  "지난번에 이 패턴으로 스모크 오판 났었는데요".
- **B15 세션 서기** `[기억][모델]`
  개발 세션의 결정·근거를 자동 기록 → 다음 세션의 컨텍스트 브리핑.
  "지난 세션에서 어디까지 했지?"가 완벽하게 답해짐.

## C. 자기 개선 데스크탑 — "매 세션이 끝나면 조금 나아진다"

핵심: 개발 대상과 사용 환경이 같은 머신. 에이전트가 사용자의 불편을
추측이 아닌 관찰로 알고, 수정→빌드→검증→적용 루프를 닫는다.

- **C1 사용 불편 자동 발견** `[기억][모델]`
  "이 버튼 하루 40회 클릭", "이 기능 켰다 끈 적 12번" → 이슈화 → 제안.
- **C2 불평 → 패치 → 카나리 → 적용** `[실행][모델]`
  "태스크바 시계 잘 안 보여" → 브랜치 패치 → 별도 인스턴스 스모크 →
  레이아웃 복원과 함께 재시작 적용 ("재시작하면 반영됩니다" UX).
- **C3 자가수리** `[실행]`
  기본값·키바인딩·사소한 버그는 자동 적용, 큰 변경만 승인 대상.
- **C4 야간 진화** `[실행][모델]`
  밤에 백로그에서 작은 기능 구현 → 아침에 "오늘의 변화 3건" diff 리뷰.
- **C5 취향 학습** `[기억][모델]`
  사용자가 되돌린 변경의 이유를 학습해 다음 제안의 질 향상.
- **C6 역방향: 사용이 곧 개발** `[기억]`
  데스크탑을 쓸수록 에이전트가 커밋/이슈를 생산하는 OS.
- **C7 회귀 감시 기간** `[기억][보다]`
  패치 적용 후 N일간 관련 이벤트 추적 → 이상 징후 시 자동 보고,
  사용자가 되돌리면 그 이유까지 기록.
- **C8 A/B 실험 프레임워크** `[기억][모델]`
  후보 변경 두 가지를 교대로 적용, 사용자의 실제 행동(재사용률, 되돌림 여부)으로
  선호 판정. "감으로"가 아니라 데이터로 취향을 확인.
- **C9 취향 파일** `[기억]`
  사용자의 선호(정렬 순서, 기본 크기, 닫기 습관, 어투)가 구조화된 파일로
  축적 — 모든 에이전트 제안이 이 파일을 참조. 취향은 진화하는 문서.
- **C10 신뢰 통계** `[기억]`
  에이전트 제안의 수용/기각률 공개 → 자율성 단계를 올리고 내리는 근거.
  "이번 달 자가수리 14건, 되돌림 1건".
- **C11 되돌림 일지** `[기억]`
  모든 자동 변경의 기록 + 이유 + 원클릭 롤백. 자기 개선의 안전망.

자율성 사다리: 0 관찰자(리포트만) → 1 제안자(diff 승인) → 2 자가수리(사소한 것
자동) → 3 야간 진화(자율). 신뢰에 따라 시기별로 오르내린다.

방어선: 카나리 배포(별도 인스턴스), git 되돌리기, 승인 게이트, receipt 기록.

## D. 마진 코멘트 — "에이전트가 말을 건다"

문서 코멘트처럼 대상(앵커)에 붙여 개발자에게 전달되는 비침습 메시지.
형태: `{앵커, 작성자, 종류, 증거, 상태, 스레드}`.

- **D1 관찰 코멘트** `[기억]`
  근거(이벤트 히스토리)를 첨부한 발견 보고. UI 요소에 배지로 표시.
- **D2 동작 설명 코멘트** `[기억]`
  에이전트가 한 동작의 "왜". receipt가 기록이라면 코멘트는 메시지 —
  의도 설명이 신뢰를 만든다.
- **D3 가설 코멘트** `[기억][모델]`
  결론이 아니라 가설을 남겨 개발자가 판정. "정렬이 불편한 건 순서 때문일 겁니다.
  실험해볼래요?" — 미래의 나를 위한 검토 메모.
- **D4 디자인 코멘트** `[캡처][모델]`
  "이 간격은 DPI 150%에서 겹칩니다" — 스크린샷 첨부.
- **D5 코멘트 허브** `[보다]`
  개발자용 받은편지함 창. 우선순위·종류별 트리아지.
- **D6 레포 브리지** `[기억]`
  수용된 코멘트 → 증거 첨부 이슈/문서 TODO로 승격. 데스크탑 사용이
  백로그를 생산.
- **D7 스레드 학습** `[기억][모델]`
  개발자의 기각 답변("이건 의도된 배치임")에서 취향 학습.
- **D8 코드 앵커 코멘트** `[보다][기억]`
  UI 요소 코멘트가 소스 위치와 연결 — "이 버튼(taskbar.c:212)의 클릭율이...".
  데스크탑 관찰이 코드에 직접 달림.
- **D9 주간 다이제스트** `[기억][모델]`
  한 주의 코멘트·자기개선 활동 요약 — "코멘트 12개 중 4개 수용, 신규 가설 3개".
- **D10 코멘트 서식 표준** `[모델]`
  가설 코멘트의 표준 템플릿: 가설 / 근거 / 예측 / 검증 비용 — 판정이 쉬워짐.
- **D11 코멘트 정렬** `[모델]`
  효과 크기 × 검증 비용으로 우선순위 정렬 — 허브에서 뭘 먼저 볼지 결정.
- **D12 코멘트 자동 마감** `[보다]`
  앵커 대상(UI 요소/창)이 사라지면 관련 코멘트 자동 마감·아카이브 —
  유령 코멘트 방지.
- **D13 수용 패턴 학습** `[기억][모델]`
  어떤 종류의 코멘트가 수용되는지 학습 → 다음 세션의 코멘트 필터링.
  "디자인 코멘트는 잘 받아주시는데, 성능 제안은 기각률이 높네요".

소음 방어: 세션당 코멘트 예산, 우선순위 문턱, 기각된 주제 재제기 금지,
