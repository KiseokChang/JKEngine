# jkdesktop AI 에이전트 — 시나리오 카탈로그

- 날짜: 2026-09-09
- 성격: 브레인스토밍 결과물. 구현 설계는 별도 문서:
  `2026-09-09-desktop-agent-platform-design.md`
- 목적: "에이전트가 jkdesktop에서 **무엇을 할 수 있는가**"의 전체 지도.
  각 시나리오는 필요한 능력을 태그로 표기한다.

**능력 태그**: `[보다]`=구조화 상태/이벤트 읽기, `[만지다]`=창/앱 조작,
`[실행]`=앱 실행·터미널, `[캡처]`=창 픽셀 캡처, `[기억]`=이벤트/receipt 히스토리,
`[협업]`=에이전트 간 통신, `[모델]`=LLM 추론 필요

## A. 사용자 일상 — "데스크탑이 나를 위해 일한다"

- **A1 말로 조작** `[만지다][실행][모델]`
  "터미널이랑 브라우저 나란히 띄워줘" → 앱 실행 + 레이아웃 배치. 실행 전
  미리보기 오버레이로 확인, 되돌리기 칩 제공.
- **A2 업무 모드 저장/복원** `[보다][만지다][기억]`
  현재 창 배치를 "작업"·"영상" 등 이름으로 저장. 아침에 어제 상태 그대로 복귀.
- **A3 반복 패턴 → 자동화 승격** `[기억][모델]`
  같은 동작 3회 반복 감지 → "버튼으로 만들어드릴까요?" → 태스크바 단축 버튼 승격.
- **A4 포커스 문맥 질의** `[보다][모델]`
  포커스된 터미널의 에러 해석, 브라우저 페이지 요약, 열린 문서 질의응답.
  짧은 답은 팔레트에, 긴 답은 에이전트 패널 창으로.
- **A5 알림 트리아지** `[보다][모델]`
  흩어진 알림을 모아 중요도 순 요약. "중요한 건 2개예요".
- **A6 예약/트리거** `[보다][실행]`
  "빌드 끝나면 알려줘", "30분 뒤에 회의 알림" — 이벤트 구독 + 타이머.
- **A7 접근성 비서** `[보다][캡처][모델]`
  화면 읽어주기, UI 요소 설명, 음성 완전 조작. 커스텀 데스크탑이므로
  접근성 API부터 넣을 수 있는 OS급 기능.
- **A8 통합 검색** `[보다][기억][모델]`
  "어제 그 PDF 창 어디 있지?" — 창·파일·터미널 출력·영상 장면 통합 검색.
- **A9 자리 비움 정리** `[보다][만지다]`
  user_idle 감지 → 레이아웃 저장 + 민감 창 최소화 + 잠금 제안.
- **A10 창 청소부** `[보다][만지다]`
  오래 포커스 안 받은 창 목록 → 개별 [닫기] 승인 후 정리.

## B. 개발자 동료 — "동료가 하나 더 생긴다"

- **B1 테스트 러너** `[실행][보다]`
  빌드 → 실행 → probes 스모크 → 로그 판독 → 통과/실패 리포트 자율 수행.
- **B2 크래시 수사관** `[보다][기억][모델]`
  크래시 발생 시 관련 로그·직전 이벤트를 수집해 "원인 3줄 요약" 리포트.
- **B3 로그 회귀 탐지** `[보다][기억]`
  빌드 간 로그 diff에서 새로 생긴 warning/에러 패턴만 추려 보고.
- **B4 앱 공장** `[실행][만지다][모델]`
  "2048 변형 하나 만들어줘" → .jkx 생성 → 자기가 실행·검증까지.
- **B5 리팩터링 감시자** `[보다][실행]`
  3-lib 분할 작업 중 의존성 방향 위반·빌드 깨짐을 상시 감시·보고.
- **B6 문서 관리인** `[보다][모델]`
  코드 변경 감지 → docs/*.md 해당 섹션 갱신 제안 (마진 코멘트로).
- **B7 버그 재현 담당** `[기억][실행]`
  버그 보고 시 이벤트 히스토리에서 조작 순서를 재현해 확인.
- **B8 성능 코치** `[보다][기억][모델]`
  프레임 드랍 패턴 분석 → "OSR 창 3개 떠있을 때만 발생하네요".

## C. 자기 개선 데스크탑 — "매 세션이 끝나면 조금 나아진다"

핵심: 개발 대상과 사용 환경이 같은 머신. 에이전트가 사용자의 불편을
추측이 아닌 관찰로 알고, 수정→빌드→검증→적용 루프를 닫는다.

- **C1 사용 불편 자동 발견** `[기억][모델]`
  "이 버튼 하루 40회 클릭", "이 기능 켰다 끈 적 12번" → 이슈화 → 제안.
- **C2 불평 → 패치 → 카나리 → 적용** `[실행][모델]`
  "태스크바 시계 잘 안 보여" → 브랜치 패치 → 별도 인스턴스 스모크 →
  레이아웃 복원과 함께 재시작 적용 ("재시작하면 반영됩니다" UX).
- **C3 자가수리** `[실행]`
  기본값·키바인딩·사소한 버그는 자동 적용, 큰 변경만 승인 대상.
- **C4 야간 진화** `[실행][모델]`
  밤에 백로그에서 작은 기능 구현 → 아침에 "오늘의 변화 3건" diff 리뷰.
- **C5 취향 학습** `[기억][모델]`
  사용자가 되돌린 변경의 이유를 학습해 다음 제안의 질 향상.
- **C6 역방향: 사용이 곧 개발** `[기억]`
  데스크탑을 쓸수록 에이전트가 커밋/이슈를 생산하는 OS.

자율성 사다리: 0 관찰자(리포트만) → 1 제안자(diff 승인) → 2 자가수리(사소한 것
자동) → 3 야간 진화(자율). 신뢰에 따라 시기별로 오르내린다.

방어선: 카나리 배포(별도 인스턴스), git 되돌리기, 승인 게이트, receipt 기록.

## D. 마진 코멘트 — "에이전트가 말을 건다"

문서 코멘트처럼 대상(앵커)에 붙여 개발자에게 전달되는 비침습 메시지.
형태: `{앵커, 작성자, 종류, 증거, 상태, 스레드}`.

- **D1 관찰 코멘트** `[기억]`
  근거(이벤트 히스토리)를 첨부한 발견 보고. UI 요소에 배지로 표시.
- **D2 동작 설명 코멘트** `[기억]`
  에이전트가 한 동작의 "왜". receipt가 기록이라면 코멘트는 메시지 —
  의도 설명이 신뢰를 만든다.
- **D3 가설 코멘트** `[기억][모델]`
  결론이 아니라 가설을 남겨 개발자가 판정. "정렬이 불편한 건 순서 때문일 겁니다.
  실험해볼래요?" — 미래의 나를 위한 검토 메모.
- **D4 디자인 코멘트** `[캡처][모델]`
  "이 간격은 DPI 150%에서 겹칩니다" — 스크린샷 첨부.
- **D5 코멘트 허브** `[보다]`
  개발자용 받은편지함 창. 우선순위·종류별 트리아지.
- **D6 레포 브리지** `[기억]`
  수용된 코멘트 → 증거 첨부 이슈/문서 TODO로 승격. 데스크탑 사용이
  백로그를 생산.
- **D7 스레드 학습** `[기억][모델]`
  개발자의 기각 답변("이건 의도된 배치임")에서 취향 학습.

소음 방어: 세션당 코멘트 예산, 우선순위 문턱, 기각된 주제 재제기 금지,
앵커 대상 소멸 시 자동 마감.

## E. 미디어·재미 — "놀이도 가능하다"

- **E1 씬 검색** `[캡처][기억][모델]`
  "해변 나오는 장면으로 가줘" — 자막/프레임 인덱싱 → jog dial seek 연결.
- **E2 자막 실시간 번역** `[모델]`
  vplayer 자막 스트림 번역·이해.
- **E3 스포일러 없는 요약** `[모델]`
  "지금까지 본 부분까지만 다음 화 요약해줘".
- **E4 마인스위퍼 코치** `[캡처][모델]`
  보드 프레임버퍼 직접 캡처(스크린샷 낚시 없음) → 다음 수 확률 제안.
- **E5 데스크탑 펫** `[보다]`
  이벤트에 반응하는 마스코트 — 저장하면 기뻐하고 빌드 실패하면 걱정하는.
- **E6 플레이리스트 큐레이션** `[기억][모델]`
  재생 패턴 학습 → 큐 관리·추천.

## F. 생태계·멀티 에이전트 — "에이전트도 앱이다"

- **F1 MCP 서버** `[보다][만지다][실행]`
  외부 에이전트(Claude Code 등)가 jkdesktop을 조작 — 데스크탑이 거대한 tool.
- **F2 agent = .jkx 앱** `[협업]`
  에이전트도 패키지로 설치. "리서치 에이전트", "코딩 에이전트"가 앱처럼 배포.
- **F3 QuickJS 앱에 AI** `[모델]`
  스크립트 앱에서 `agent.summarize(...)` 등 호출 — 플랫폼 전체 AI-capable.
- **F4 코더+리뷰어 협업** `[협업][실행]`
  빌드 실패 이벤트 → 코더 에이전트 자동 참여 → 패치 제안 → 리뷰어 검토.
- **F5 능력 레지스트리** `[협업]`
  에이전트 간 위임 — "누가 검색 능력 있지?" → 이벤트 버스로 요청.
- **F6 리서치 에이전트** `[보다][모델]`
  OSR 브라우저 멀티탭 조사 → 결과를 에이전트 패널 창으로.

  "오늘 코딩 4시간, 영상 1시간, 회의 창 2개".

## 우선순위 관찰 (브레인스토밍 시점의 직감)

- **즉시 가치 + 낮은 비용**: B1(테스트 러너), F1(MCP 서버) — 이미 있는 조각
  (probes, 로그, 터미널)의 조립.
- **이 시스템만의 정체성**: C(자기 개선 데스크탑) + D(마진 코멘트) — Windows에서는
  불가능, jkdesktop에서는 사용자=개발자=승인자가 한 명이라 설계 가능.
- **쇼케이스**: E4(마인스위퍼 코치) — 픽셀 캡처 능력을 가장 그림 있게 증명.
- **선행 조건**: D(코멘트)와 C(자기 개선)는 G3/G5(receipt/타임라인)에 의존 —
  기록 계층이 먼저.
