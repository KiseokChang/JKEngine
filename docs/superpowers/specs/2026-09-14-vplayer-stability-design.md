## 1. 설계

### 1a. ① 이상한 파일 크래시/멈춤 → 비동기 오픈 + 방어막

1. **비동기 오픈**: `Open()`의 디먹스/코덱 초기화 전체를 워커 스레드 1단계로.
   UI는 즉시 "여는 중..." 상태(취소 버튼)를 보여주고, 완료 시 openError_ 또는
   재생 개시. `AVFormatContext.interrupt_callback` + 타임아웃(10s, 콜백이
   deadline 초과 시 1 반환) — 정지 파일도 10초 내 취소 가능.
2. **차원 상한**: videoW/H 상한(각 8192, W*H*4 ≤ 256MiB) 초과 시 openError_로
   거부 — 디코더 열기 전(:323 근방) 검사.
3. **예외 방어막**: 워커 루프 전체 try/catch(catch(...) → lastError 설정 +
   ended 처리, terminate 방지), UI `OpenPath`의 new PlayerCore try/catch →
   openError_. (예외는 수단이 아니라 최후의 방벽 — 정상 경로는 여전히 에러코드.)
4. **읽기 오류 분류**: `av_read_frame` — `AVERROR_EOF`만 ended, EAGAIN은 재시도,
   기타 오류는 lastError + "다시 시도" 가능 상태. 디코드 오류는 카운터만
   (로그 수준, UI 폭탄 아님) — 연속 N건 실패 시 lastError 노출.

### 1b. ② 오디오 끊김 → 오디오 우선 + 가시화

1. **오디오 우선 디코드**: 단일 워커 유지(스레드 분리는 이번 패스 아님 —
   락/수명 재설계 리스크 대비 효과 미실측). 정책: 링 버퍼가 저수위(예: 200ms)
   이하면 오디오 패킷을 연속 디코드해 충전(오디오 리필 우선), 비디오 디코드는
   고수위 회복 후. videoQ 백프레셔 대기(:511) 중에도 오디오는 계속.
2. **언더런 카운터**: 콜백 무음 분기(:446)에서 카운트 — 진단용 상태 텍스트
   (디버그 빌드/스테이터스 라인).
3. **디바이스 실패 가시화**: SDL 오디오 오픈 실패 시 stderr만이 아니라 상태
   텍스트 "오디오 장치를 열 수 없음(무음 재생)" 노출. 기존 무음 폴백 정책 유지.
4. **읽기 오류 노출**: 1a-4와 연동 — 중단 시 이유 표시(현재 "다시 재생"만).

### 1c. ③ 시크 멈춤/틀어짐 → UI 비차단 + 시크 실패 정정

1. **UI 비차단**: `DoSeekLockedStage1`이 `m`을 잡은 채 `avformat_seek_file`을
   도는 구조가 본질. 픽스: 시크 I/O 직전 `m` 해제 — stage1을 (a) `m` 하에서
   큐/클록 재기준 (b) `m` 해제 후 `avformat_seek_file` (c) 재잠금 후 검증 +
   계속, 3단으로 분해. `seekGen`으로 검증 단계에서 최신 시크인지 확인(구식이면
   폐기). UI의 `SnapNow`는 그대로 — 이제 I/O가 락 밖이라 밀리초 급.
2. **시크 실패 정정**: `avformat_seek_file` 실패 시 (a) 클록 재기준 되돌림
   (이전 위치 복원) (b) lastError "시크 불가 위치" 일회 표시 (c) 폴백으로
   현재 위치에서 decode-forward 폐기 스캔(장거리 시크는 포기, 근거리만).
   시크 불가 컨테이너에서 "클록만 이동하는 정지 화면" 소멸.
3. **스크럽 중 UI**: 시크 진행 중 마지막 프레임 유지 + 상태 표시(기존 postSeekJump
   패턴 유지).

### 1d. 조그 휠 → 마우스 휠 스크럽

- 노브 hover(`hot` :900)에서 `io.MouseWheel` 틱 → `jogTarget_ += dy·sPerRev/16`
  (틱당 1/16회전 상당 — 드래그 감도와 동계열), 기존 40ms 디바운스 `SeekScrub`
  재사용(:948).
- **릴리스 정의**: 휠엔 릴리스 이벤트가 없으므로 휠-아이들 타임아웃(400ms
  무입력)에서 드래그 릴리스 경로와 동일하게 마무리 — 프레임 스냅 precision
  `Seek` + `SetJog(false)` + 일시정지 상태 복원(:916-925 재사용).
- **일시정지 시맨틱**: 드래그 경로와 동일 — 스크럽 시작 시 자동 일시정지, 종료
  시 원상복구(:903-914 계승). 재생 중 휠 스크럽도 `SetJog(true)`가 오디오
  디코드를 억제(:479)하므로 안전.
- 드래그와 휠이 같은 jogTarget_/디바운스를 공유 — 동시 입력 시 최신 승리
  (wantSeek 병합과 동일 철학).

## 2. 검증

- 빌드 exit 0 + `jkdesktop test` 0 failures + 프로브 전량.
- 실측: ① 이상한 파일 3종(잘린 mp4, 0바이트, 대형 해상더 헤더 조작본) — 크래시
  0 + 10초 내 취소 가능 + openError_. ② 오디오 끊김 — 고해상도 파일 재생 중
  언더런 카운터 비교(픽스 전/후), 드롭 체감 감소. ③ 시크 — 인덱스 없는 AVI에서
  시크 UI 정지 시간, 시크 실패 시 클록/화면 정합. ④ 휠 — 노브 hover에서 휠
  스크럽 + 400ms 후 스냅 + 상태 복원.
- 스크린샷: 오류 상태/여는 중 상태 각 1장.

## 3. 리스크

1. **stage1 락 해제 분해**가 가장 위험 — `m`이 보호하던 불변식(큐/클록/코드cs
   상태)이 I/O 중 노출. seekGen 검증 + "구식이면 전부 폐기"로 봉합. 실패 시
   대안: UI만 SnapNow 회피(간이 완화)로 강등.
2. **오디오 우선 정책의 굶김 반전** — 비디오가 굶으면 표시 게이트가 프레임을
   떨어뜨림(현재도 그렇게 동작). 저수위 역치 튜닝은 실측 의존.
3. **interrupt_callback의 취소 정합** — 콜백이 1을 반환하면 FFmpeg가
   AVERROR_EXIT 반환. 오픈 취소 경로에서 컨텍스트 정리 순서 주의.

| D1-cor (실행 교정, T1 실측) | **interrupt_callback은 블로킹 파일 I/O를 깨지 못한다** — FFmpeg 7.1.101 실측: file 프로토콜 read/probe 루프에서 콜백 호출 횟수 0 (최소 재현, T1 보고서 §4c). 10s 데드라인·취소 플래그는 FFmpeg가 블로킹 호출에서 반환할 때만 유효 — 침묵 파이프/죽은 네트워크 마운트 같은 무한정 반환 없는 I/O는 스펙 기계로 못 끊는다. **진짜 방어선은 Abandon**: TryClose(2s) 실패 → 워커 detach + PlayerCore 의도적 프로세스 수명 누수(UI 스레드 join 프리즈 대신). 취소/타임아웃 UI 표시는 "여는 중"에서 계속 노출되는 한계 기록 | T1 실측 + 리뷰 MINOR-4 확인 — "열기 시간 초과" 분류는 이 FFmpeg 빌드에서 사실상 도달 불가(코드 남김 — I/O가 반환하는 소스에선 유효) |
| 직감 | 라이브러리의 "취소 가능" 문언은 프로토콜별로 측정해야 한다 — interrupt_callback은 네트워크 프로토콜용이고 파일 프로토콜은 폴링 지점이 없다. 취소 설계는 콜백 등록이 아니라 "끊지 못할 I/O에 대한 수명 포기" 설계까지 포함한다 | T1 §4c 실측 (cb 호출 카운터 0) |
| 직감 | "크래시"의 대부분은 UI 스레드 동성(同姓) 문제다 — FFmpeg를 어느 스레드에서 부르느냐가 안정성의 절반 | §0 (Open/allocate가 UI·워커 무방비) |
| 직감 | 오디오 클록(오디오가 마스터)은 건드리지 않는 것이 3증상 중 2개의 해법 — 비디오가 오디오를 따르는 구조는 유지 | §0 클록 사실 |
