## 1. 배경과 동기

jkdesktop은 자체 윈도우 서버(SDL2) 위에 앱(DLL/.jkx 패키지), 태스크바, ImGui, OSR
브라우저, ConPTY 터미널, vplayer, QuickJS 스크립팅 브리지를 갖춘 데스크탑
플랫폼이다. 여기에 AI 에이전트를 붙이면 Windows 데스크탑 자동화와 결정적으로 다른
강점이 생긴다:

- 에이전트가 OCR/스크린샷 추측 없이 **구조화된 윈도우 상태**(창 목록, 포커스,
  z-order, 앱 이벤트)를 네이티브로 얻는다.
- 자동화 API 표면을 처음부터 설계할 수 있다 — 자동화가 해킹이 아니라 시민권자다.
- 특정 창의 프레임버퍼를 직접 캡처할 수 있다.

브레인스토밍 결과, 에이전트의 모든 얼굴(사용자 커맨드 바, 외부 MCP 에이전트,
개발/테스트 자동화)이 **동일한 능력 집합**을 요구한다: 윈도우·앱·이벤트·로그를
구조적으로 조회/조작하는 API. 이 문서는 그 공통 기반인 **Desktop Agent API**와
그를 실어 나르는 브로커를 정의한다.

## 2. 아키텍처

```
[커맨드바/패널창]  [MCP 서버]  [probes/자동화 스크립트]   ← 세 얼굴 (프론트)
        └───────── Desktop Agent API ─────────┘       ← 하나의 API
                        │
              [브로커 jkagentd]                        ← 이벤트 버스·권한 관문·receipt
                        │
              [윈도우 서버 (jkserver)]                  ← 이벤트 소스 + API 실행
```

핵심 원칙:

- **하나의 API, 여러 얼굴.** 커맨드 바의 "창 두 개 나란히"와 MCP의 `set_layout`은
  같은 함수를 호출한다. 에이전트 기능을 따로 구현하지 않고, 플랫폼이 자동화를
  일등 시민으로 갖게 된다.
- **브로커는 사이드카다.** jkagentd가 죽어도 데스크탑은 정상 동작한다. 이벤트
  버스, 권한 검사, receipt 기록, (4단계)장치 접근 관문까지 전부 브로커에 둔다.
- **3-lib 분할과 정렬.** Agent API는 jkserver 프로토콜의 일부로 설계한다. 분할이
  완성되면 MCP 서버는 얇은 클라이언트가 되고, 에이전트가 서버 설계의 증명서가 된다.

## 3. Desktop Agent API (1단계)

MCP tool 형태로 노출하는 첫 세트:

| Tool | 내용 |
|---|---|
| `list_windows` | 앱/제목/geometry/포커스 — 구조화 정보, 스크린샷 추측 없음 |
| `launch_app` | 앱 이름 또는 .jkx 경로로 실행 |
| `close_window` | 창 종료 (권한: control, 인라인 승인 대상) |
| `focus_window` | 포커스 전환 |
| `save_layout` / `restore_layout` | 창 배치 스냅샷 저장/복원 — 데스크탑 undo의 기반 |
| `read_log` | jkdesktop/term 로그 tail·필터 |
| `terminal_exec` | ConPTY 세션 생성 + 출력 스트림 읽기 (권한: execute) |

전송: stdio MCP ↔ jkagentd ↔ 윈도우 서버 IPC. MCP 서버는 자체 UI/상태를 갖지 않는
얇은 어댑터다.

## 4. 이벤트 버스 (1단계에 최소 포함)

**소스**: 윈도우 서버 코어(창/앱/입력 이벤트를 이미 알고 있음) → 브로커가 구독·배포.

**토픽 분류학**:

- 윈도우: `created / destroyed / focused / unfocused / moved / resized / minimized / restored`
- 앱: `started / exited / crashed / hung`
- 입력: `user_idle(sec)` / `user_active`
- 터미널: `output` (정규식 매칭 필터 지원)
- 미디어: `player.paused / track_changed`

**페이로드 예시**:

```json
{"topic":"window.destroyed", "app":"vplayer", "win_id":42, "ts":...}
{"topic":"terminal.output", "session":3, "text":"...error C2065...", "match":"error"}
{"topic":"app.crashed", "app":"minesweeper", "exit":139}
```

**구독 모델**: 토픽 필터 + payload 정규식 등록 → 비동기 큐 배달. 구독자별 rate
limit(초과 시 drop + 통계), 미배달분은 dead-letter. 1단계에서는 구독자가
MCP `subscribe` tool과 자체 큐만 있어도 충분하다.

**자동화 스크립트(2단계)**: QuickJS로 트리거 스크립트 작성, .jkx 매니페스트에
트리거 선언:

```js
on("terminal.output", {match: /error C\d+|fatal/i}, async (e) => {
  await desktop.notify("빌드 실패 감지", {open_log: e.session});
});
on("user_idle", {sec: 1800}, () => desktop.layout.save("away"));
```

**버스 분리 원칙(외부 리뷰 반영, Part 9-G1)**: 이벤트 버스는 제어/상태 버스와
데이터 스트림 버스로 나눈다. 창·앱·입력 이벤트는 가벼운 JSON 이벤트로 제어
버스에 흐르고, 오디오/카메라 프레임 같은 고속 데이터는 공유 메모리로 필요한
구독자에게만 라우팅한다(1단계는 제어 버스만). 원본 미디어는 버스에 태우지
않는다 — 로컬 처리를 거쳐 "사용자 부재중" 같은 의미적 이벤트(semantic event)만
제어 버스에 실린다(§8).

## 5. 권한/프라이버시 모델

| 등급 | 내용 | 기본값 |
|---|---|---|
| observe | 창 목록·이벤트 구독 | 앱별 옵트인 |
| control | 포커스·이동·닫기·레이아웃 | 닫기는 인라인 승인 |
| execute | 앱 실행·terminal_exec | 매번 또는 세션 승인 |
| capture | 창 픽셀 캡처 (observe와 별도) | 재미/분석 기능만 요청 |
| files / network | 파일 접근·모델 API 호출·외부 서비스 | 설치 시 선언 + 첫 실행 승인 |
| 듣기 / 보기 / 감지 | 마이크·카메라·센서·장치 상태 (4단계, Part 7-N29) | 설치 시 선언 + 물리 활성 표시기(N7) |

- **매니페스트 확장** (.jkx 2단계): `permissions: [observe, control:close?confirm, execute:apps]`
  형태로 등급+조건을 한 줄 선언. 1단계에서는 MCP 클라이언트(외부 에이전트)에
  세션 단위 승인을 적용한다.
- **강제 지점**: 모든 API 호출은 브로커 관문 통과. 캐퍼빌리티 토큰 검증. 승인
  필요 동작은 커맨드 바 인라인 프롬프트로 위임(2단계; 1단계는 콘솔/알림 승인).
- **receipt**: `{ts, agent, call, args요약, result, 승인자(user/auto)}` append-only
  로그. 모든 조작 동작이 기록된다. 타임라인 쿼리의 백엔드.
- **타임라인 프라이버시**: receipt 보존 기본 7일, 앱별 observe 옵트아웃("비밀 창"),
  설정에서 전체 끄기.

## 6. 단계별 구현 계획 (구체화)

### 6.0 진화 원칙 — 호스트 데스크탑에서 100% 채택으로

JKWindow는 이미 Windows와 Linux 양쪽에서 돌아간다. 단계의 목표는 기능 전진이
아니라 **채택률 전진**이다: Windows/Linux 기본 데스크탑을 쓰던 시간이 조금씩
jkdesktop으로 옮겨 가는 것. 모든 기능을 다 갖추지 않아도 된다 — 어떤 기능이
필요한지는 시나리오 카탈로그와 실사용 이벤트가 결정한다.

- **"떠나는 이유"가 백로그다.** 사용자가 jkdesktop 대신 호스트 데스크탑으로
  나가는 지점(아직 없는 앱, 한글 IME 미지원, 캡처 불가 영역...)은
  `adoption.leave_reason` 이벤트로 관측 가능한 백로그 소재다.
- **플랫폼 중립 계층부터.** Agent API·브로커·이벤트 버스는 OS 무관하게 설계하고,
  플랫폼 차이(입력 장치, 오디오/캡처 스택)는 얇은 어댑터로 흡수한다 — Windows와
  Linux에서 어댑터만 바뀌고 위 계층은 공유.
- 채택률은 receipt+이벤트 버스로 측정한다: "이번 주 내 세션 중 jkdesktop 비율".
  M1(개발 세션 일부) → M2(개발 워크플로우 상주) → M3(일상 일부) →
  M4(부팅 셸 — Windows/Linux 양쪽에서 100%).

### 6.1 1단계 — Desktop Agent API + 브로커 + MCP (M1)

**컴포넌트**: jkagentd 사이드카, 서버 코어 agent 커맨드 7종, 이벤트 버스 최소판,
receipt JSONL, 세션 승인 권한 관문, stdio MCP 어댑터.

**구현 순서**:
1. 서버 코어에 7 tool을 프로토콜 커맨드로 추가 — ShellActivate/WindowListSubscribe
   패턴 재사용. save/restore_layout은 기존 레이아웃 스냅샷 직렬화를 재사용.
2. jkagentd: MCP stdio ↔ 서버 IPC 브리지 + 이벤트 발행 큐 + receipt 파일
   (append-only) + `permissions.json` 세션 승인.
3. probes 연동: `engine/tools/probes/*.ps1`이 MCP `launch_app`/`read_log`로
   승격되는 형태 — 빌드 → launch → probe → 판정 → 리포트.

**완료 조건**: Claude Code(MCP)가 "메모장 두 개 나란히"를 승인 포함해 수행,
receipt 3건 이상 기록, 토큰 없는 호출 거부 테스트 통과.

### 6.2 2단계 — 커맨드 바 + 트리거 스크립트 (M2)

- **커맨드 바**: 태스크바 통합 팔레트(`Alt+Space`), ImGui 렌더. 슬래시 = 결정적
  (로컬 파싱·즉시 실행), 자연어 = 파서→에이전트 위임. 실행 전 레이아웃 미리보기
  오버레이 + undo 칩, 인라인 승인 UX.
- **트리거 스크립트**: QuickJS `on(topic, filter, handler)`, .jkx 매니페스트
  `triggers:` 선언. 첫 번들 3개 — 빌드 실패 알림, 30분 idle 레이아웃 저장,
  앱 크래시 배지.
- **마진 코멘트(관찰자 모드)**: 에이전트가 UI 요소/디자인/자기 동작에 앵커
  코멘트(관찰/근거/가설)를 남기고 코멘트 허브 → 백로그 브리지로 전달.
- 신규 앱(§7): 알림 센터, 스크린샷 도구.

**완료 조건**: 결정적 커맨드의 80%가 커맨드 바로 처리, 트리거 1개가 실빌드
실패를 잡아 알림 센터에 도달.

### 6.3 3단계 — 셀프-이머브 데스크탑 (M2.5)

- 코멘트 백로그 → 패치 브랜치 → **카나리아 인스턴스**(별도 jkdesktop 프로세스 +
  스모크) → 승인 → 적용(레이아웃 스냅샷 복원) → 회귀 감시 → 롤백 저널.
- 자율성 사다리 0(제안만)→1(카나리아 검증 후 적용)→2(제한 영역 자동)→3(트리거
  조건부 자동). 취향 파일(taste file)이 방향 결정.
- **신뢰 점수와 도메인 캡(Part 9-G4)**: 승격은 시간이 아니라 정량 지표로 —
  신뢰 점수 = 수용 횟수 − 되돌림 횟수 × 가중치. 도메인별 상한: UI 테마·게임
  코치는 레벨 3 허용, jkserver 코어 리팩터링 감시는 영구 레벨 1(제안자) 캡.
- **잠금 선점 순위(Part 9-G3)**: 동시 수정 충돌(S9/R10) 대비 — 사용자 프롬프트
  기반 외부 에이전트(Claude Code) > 플랫폼 내장 코디네이터 > 백그라운드 야간
  진화 순 선점권. 하위 작업은 잠금 보유자에게 양보하고 결과를 코멘트로 남긴다.

### 6.4 4단계 — 장치·외부 세계 (M3, §8)

- 장치 게이트가 브로커에 합류: 마이크/카메라/센서 토픽, §5 권한 표의 장치 행.
- 능력 태그 확장: [듣다][말하다][카메라][연결][감지].
- 시나리오 기능: 회의 모드(터미널 에러 → 알림 센터 + 브라우저 참조 열기), 센서
  트리거, 음성 커맨드. 신규 앱(§7): 설정 허브, 장치 활성 표시기.

### 6.5 채택 체크포인트

| 마일스톤 | 채택 신호 (이벤트로 측정) |
|---|---|
| M1 | probes/자동화가 jkdesktop 세션 안에서 돌기 시작 |
| M2 | 개발 워크플로우(빌드·테스트·로그)가 커맨드 바/트리거로 상주 |
| M3 | 미디어·회의·센서 시나리오가 호스트 데스크탑 대신 jkdesktop에서 열림 |
| M4 | 부팅 셸 = jkdesktop — Windows/Linux 호스트에서 100% |

채택이 정체되면 `leave_reason` 기록이 우선순위 판단 근거가 된다.

### 6.6 앱 정복 순서 — 단순한 앱부터 (병행 트랙)

단계(6.1~6.4)와 병행해 앱 단위 "정복"을 진행한다. 정복 = 에이전트가 그 앱을
실행·관찰·조작·검증·회복까지 완주하는 것. 기존 probes 스모크
(`engine/tools/probes/*.ps1`)가 각 앱 정복 테스트의 씨앗 — 스모크가 정복으로
승격된다.

정복 사다리 (단순 → 복잡, 상태 노출 기준):

1. 마인스위퍼 — 단일 창·이산 클릭·로그 판정 (probes가 이미 절반 검증)
2. 테트리스 — 60fps 입력 타이밍
3. scriptdemo/passworddemo — 스크립팅 브리지 ↔ `agent` tool 연결
4. taskmgr — 구조화 테이블 리드 (구조적 관찰의 원형)
5. 터미널 — ConPTY 스트림 (1단계 terminal_exec와 즉시 접합). 정복 시점이
   변곡점 — GDB 등 디버거 자동화가 연결되며 개발자 동료 시나리오가 활성화된다
   (Part 9-G6)
6. vplayer — 타이밍 민감 미디어 (조그 자동화·씬 인덱스)
7. 브라우저 — CEF OSR, 가장 어려운 표면
8. 최종 보스: 태스크바/셸 자신 — 특권 클라이언트 조작 (게이트 뒤)

정복된 앱마다 "jkdesktop에서만 되는 자동화"가 생기고 §6.5 채택 체크포인트에
반영된다. 정복 배지는 런처/에이전트 관리자에 표시. 정복 순서는
`leave_reason` 백로그가 재배열한다. 시나리오 문서 Part 8(P1~P16, S11) 참조.

## 8. 장치·외부 세계 I/O 계층 (4단계)

- **브로커 = 권한 중재자(PEP)**: 브로커는 장치 I/O를 직접 하지 않는다 — 최소
  권한으로 격리된 드라이버 에이전트(`audio_agent.jkx`, `camera_agent.jkx`)가
  실제 접근을 담당하고, 브로커는 이들이 버스에 퍼블리시할 권한이 있는지만
  검증한다(Part 9-G2). 사이드카 격리(R7 방어)와 일치.
- **장치 데이터는 의미적 이벤트로**: 마이크/카메라/센서는 이벤트 소스이자 권한
  대상. 앱은 매니페스트에 선언, 물리 활성화는 표시기(N7)와 연동. 원본 프레임은
  공유 메모리로 구독자에게만 가고, 버스에는 로컬 처리 결과(semantic event)만
  실린다(§4 버스 분리 원칙).
- **로컬 처리 원칙**: 카메라/바이오 데이터는 로컬 처리 우선 — 클라우드 전송은
  network 권한 + 첫 사용 승인.
- **이식성**: Windows(WASAPI/DirectShow)·Linux(ALSA/V4L2) 어댑터를 jkagentd가
  흡수 — 앱/에이전트는 게이트 API만 본다. JKWindow의 듀얼 플랫폼이 여기서
  비용을 나눠 갖는다.

## 9. 리스크와 방어

| 리스크 | 방어 |
|---|---|
| 클라우드 왕복 지연이 데스크탑 UX 즉각성을 깬다 | 결정적 커맨드(실행/레이아웃)는 로컬 파싱, 무거운 추론만 에이전트 위임 |
| 환각으로 잘못된 조작 | undo(레이아웃 스냅샷) + 승인 게이트 + receipt — 3중 방어 |
| 이벤트 버스 스팸/폭주 | 구독자별 rate limit + dead-letter |
| 브로커 크래시 | 사이드카 격리 — 데스크탑 본체와 독립 수명 |
| 장치 프라이버시 | 물리 활성 표시기 + 설치 시 권한 선언 + 로컬 처리 원칙 |
| 셀프-이머브 진동(고치다가 깸) | 카나리아 인스턴스 + 자율성 사다리 + 롤백 저널 |
| 채택 정체 | leave_reason 백로그가 시나리오 우선순위를 재조정 |

## 10. 테스트 전략

- Desktop Agent API의 각 tool은 기존 probes 체계(`engine/tools/probes/*.ps1`,
  로그 기반 검증 플레이북 doc 15)에 편승한다: 빌드 → MCP로 launch → probe →
  `read_log` 판정 → 리포트. probes가 MCP tool로 승격되는 형태.
- 이벤트 버스는 합성 이벤트 주입으로 배달·rate limit·dead-letter를 단위 테스트.
- 권한 관문은 캐퍼빌리티 토큰 없는 호출의 거부를 테이블 기반 케이스로 검증.
- 카나리아 배포 E2E: 패치 → 별도 인스턴스 기동 → 스모크 → 승인/롤백 전 경로.
- 마진 코멘트 앵커는 anchor hash(UI 트리 경로의 해시)를 갖고 렌더링 시점에
  런타임 검증을 거친다 — 창 닫힘/레이아웃 변경 후 재부착, 유령 코멘트 차단(R1,
  Part 9-G5).
- 장치 권한: 토큰 없는 마이크 접근 거부 + 물리 표시기 점등 동기화.
- 채택 메트릭: 세션 비율 카운터가 receipt/이벤트와 대조되는지 스모크.
- 앱 정복 스위트(§6.6): 정복된 앱의 probe가 회귀 게이트로 상주 — 정복이
  풀리면(이벤트 판정 실패) 즉시 리포트가 에이전트/개발자에게 간다.
