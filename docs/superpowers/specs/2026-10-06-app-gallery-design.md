## 0. 전제 (docs/67:144 대전제 승계)

- **갤러리 = 로컬 라이브러리만.** 설치된 앱을 보여주고 실행하는 문.
  네트워크 공유·스토어·서명 검수(docs/74 §2 B/C)는 나눔 확대 2단계 —
  본 스펙 스코프 밖.
- **능력 배지 문화(docs/76)를 승계한다** — 갤러리는 배지가 켜지는 두 번째
  무대. 매니페스트의 `capabilities=` 원문을 정직하게 표기("선언 없음"도
  숨기지 않는다 — 슬롯 스트립 배지와 동일 계약).
- 워크숍 문화(docs/60·76): 사용자 슬롯·진실원 무접촉. 갤러리는 **읽기 전용**
  설비다.

## 1. 이미 있는 것 (선행 조사 — 스펙 머리)

| 설비 | 위치 | 상태 |
|---|---|---|
| 런처 .jkx 스캔 | `JKDesktopShell::ScanJkxApps` (apps/*.jkx → LauncherIcon, ICON 엔트리 디코드, 툴팁=MANI title) | **win32 전용** — `#ifdef _WIN32` |
| 콘솔 앱 스캔 | `JKDesktopShell::ScanConsoleApps` (apps/<name>/manifest.json) | **win32 전용** |
| built-in 폴백 | minesweeper·tetris·lf·hx 아이콘(Init 하드코딩) | 양 플랫폼(런처의 폰 아이콘 출처) |
| 실행 경로 | 런처 탭 → SpawnClient `--jkx <path>` / `terminal:<cmd>` | 양 플랫폼(폰 TX6 실측 — `launch_app {"jkx":...}`) |
| 컨테이너 도구 | `jkx-list`(TOC+MANI 원문 인쇄)·`slot-pack`·jkx ICON 디코드 | 양 플랫폼(TX6 posix 개방 완료) |
| 설치 | `jkctl install`(zip→스테이징→InstallFromDir, 중복/무효 매니페스트 거부) | 존재 — 갤러리와 배선 안 됨 |
| 제거 | 없음 | 갭 — §7 Q2 |
| 선례 스폰 지문 | SpawnClient 지문 trust ledger upsert(서버 부팅 1회) | 승계 |

핵심 관찰: **런처가 이미 "아이콘 갤러리"다**(아이콘+툴팁+탭 실행). 갤러리가
추가할 것은 ①텍스트 목록(아이콘 없어도 읽히는) ②메타 정보(MANI 원문·능력
선언·크기·출처) ③posix 개방(폰 런처는 현재 built-in만 보인다).

## 2. 발견 규약 (갤러리 목록의 3원 + 1)

1. `.jkx` 컨테이너 — `apps/*.jkx`, MANI 필드 소비: name·title·capabilities·
   icon(icon@2x/1x). MODL 엔트리 유무가 런처 스폰 대상 판정(jkctl promote
   주석의 스캔 규약 재용).
2. 콘솔 앱 — `apps/<name>/manifest.json`(name·cmd·icon). .jkx와 동명이면
   .jkx 우선(기존 스캔 순서 규약).
3. built-in — minesweeper·tetris 등 내장 앱 폴백 아이콘(엔진 소유 — 갤러리
   표기 "내장").
4. (결제 Q3) 워크숍 슬롯 — **제외 결정(2026-10-07)**. `state/scripts/*.js`는
   출하(slotted pack)를 거쳐야 앱이므로 갤러리에 등장하지 않는다 — 출하
   경로 하나만 유지(docs/74 문화).

동작: 스캔은 허브 앱 기동마다 재실시(캐시 없음 — 원칙 1 "평범한 파일"); 아이콘
디코드는 ScanJkxApps 선례(ICON 엔트리→stb). 아이콘 부재 = 플레이스홀더 폴백
(런처 그리드 규약 동일).

## 3. 형태 — 두 후보 (§7 Q1, 추천 = 허브 앱)

**A. 독립 허브 앱(추천)** — settings/notes/files 허브 선례의 네 번째 멤버
(예: ClientGalleryApp — 클라 프로세스, 창 1개):
- 목록: 이름·표시명·출처(.jkx/콘솔/built-in)·능력 배지·아이콘 섬네일.
- 상세: 선택 항목의 MANI 원문(jkx-list 출력 수준)·크기·경로.
- 실행 버튼 → launch_app 와이어 재용(허브 앱이 곧 발신자 — app_tool/
  agent 채널 접촉 없음).
- 이유: 메타+배지가 클라 위젯 계열 UI라 서버 셸(런처 아이콘 그리드)에 얹기
  어렵다; 워크숍 창 문화(별도 창=대면 화면)와 일치; 폰에서도 허브 앱 패턴이
  실측돼 있다(TX6 phoneprobe = 같은 스폰 경로).
- 함정 원장: 클라 허브 앱은 **자기 기기의 apps/를 읽는다** — 수신 기기
  (폰)에서는 폰의 apps/가 진실원(파일 시스템 기반이라 자동 성립).

**B. 런처 확장** — 셸 그리드에 목록 보기 전환(서버 측). 장점: 창 없이 즉시.
압박: 서버에는 텍스트 렌더러가 없다(셸 주석) — 배지·원문 표기가 불가능
수준, 메타는 툴팁 한 줄이 상한. **B 단독은 갤러리 요건 미충족** — A를
만들고 런처가 그대로 아이콘 뷰를 겸하는 자연 승계.

## 4. posix 개방 (폰 도달의 실제 본체)

- `ScanJkxApps`/`ScanConsoleApps`의 `#ifdef _WIN32` 해제 — TX6 라우트 4
  개방 선례(stdio+std::filesystem 어댑터리).
- 디렉터리 열거 win32 FindFirstFile 대응: `std::filesystem::directory_
  iterator`(TX6 slot-pack posix 레그 선례, ec 중립형 무 try/catch 규약).
- 아이콘 텍스처는 서버 소유(`host_.makeTexture`) — posix 서버에 텍스처
  부품 존재 여부 확인 필요(초안 조사 미완 — 플랜 단계에서 본서 먼저 실측,
  폰에서 ICON 부재 기본값 동작은 그 전에 확정된 폴백으로 통과).
- 셸 스폰 posix leg는 존재(플랜 G 완결 — taskbar 자동 스폰) — 갤러리 탭
  경로는 `launch_app` 와이어로 통일해 shell 측 스폰 신규 코드 불요.

## 5. 스코프 밖 (명시)

- 외부 공유·URL 스토어·서명/검수 — 로컬 대전제 밖(docs/74 2단계와 같은
  스케일에서 별도 결정).
- uninstall/업데이트 — **제외 결정(2026-10-07, Q2 스킵)**. 갤러리는 읽기
  전용 유지. 설치는 jkctl install이 이미 맡는다. 제거 도구는 별도 문에서
  사이드카·state 연쇄 정책과 함께 판단.
- 슬롯 직접 실행(워크숍 우회) — 금지(능력 게이트 문화 유지 — 출하 경로
  하나만 남긴다).
- jkctl install 자체의 변경(중복 정책·충돌 정책 원장 docs/77 §8만 승계).

## 6. 테스트 전략 (probe 선례 승계)

- **목록 CLI(서버 불요)**: 갤러리 발견 규약을 pure CLI로 1차 검증
  (probe_slot_ship의 "단일 서브커맨드, 스택 무접촉" 패턴 재용) — 3원
  발견+동명 우선순위+MANI 소비 필드를 기계 수령.
- **셀프테스트 케이스**: 허브 앱 스캔(가짜 apps/ 임시 트리 — .jkx/콘솔/
  built-in 3원 + 동명 충돌 케이스 — 1.3 캡처 트랩 계열).
- **실측**: Windows 런처에서 갤러리 앱 기동 → 실제 apps/*.jkx 목록 수령 →
  실행 버튼으로 jkx 앱 스폰. 폰: posix 스캔 개방 후 폰 런처/갤러리에
  phoneprobe 표기 확인(TX6 후속).
