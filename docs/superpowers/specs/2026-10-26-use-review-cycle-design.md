## 목적

폰/Win에서의 **실제 사용이 자동으로 수확→분류→패치/개선/재배포로 돌아오는
한 바퀴**를 실장한다 — 사용자가 대화로 붙여넣지 않아도 결함/사용 이벤트가
원문으로 모이는 것(사이클 지도의 빈 조각 3건).

## 재량 결정 원장 (D1-D6 — 기각 시 즉시 수리)

- **D1 사용 저널**: 서버(jkdesktop) 에이전트 도구 호출 1건당 append-only
  저널 1행(`state/use_journal.jsonl` — ts·tool·요약 args·ok/err) — **절대
  블로킹 없는 쓰기 실패 무시(journal write 실패 = 조용히 스킵 — 도구 응답
  무영향)**. 창 관리 동작(launch/close/focus)도 동행 기록.
- **D2 저널 형식**: JSONL 1행 1이벤트 `{"ts":ms,"tool":"...","arg":"...<=128
  자 절단","ok":true|false,"err":"..."}` — 사람이 tail로 읽을 수 있는 형태.
- **D3 수확 probe**: `engine/tools/probes/jkharvest.sh` — 서버
  agentctl(journal tail 200행+events_list+bridge_report_*.txt 목록)을 모아
  **분류 요약 원문 1회 인쇄**(결함 키워드 카운트·err 상위 최근 N건·리포트
  목록) — Win/WSL/폰 공통(agentctl 접점만이라)·폰에서도 동형(주소 미인쇄
  원존).
- **D4 체감 선언 구조화**: EYES 게이트 기록 규약 1종 —
  `EYES-<항목>: <PASS|FAIL|PENDING> — <사용자 원문 인용 1줄>` — 앞으로 모든
  라인 폐곡 원장이 이 형식의 결제 행을 쓴다(사용자 선언만 결제 원칙 불변 —
  **형식만 규약**).
- **D5 기존 도구/이벤트 원존 무변조**: events_list·read_receipts·bridge
  리포트 경로 전부 그대로 — 저널은 **추가만**(기존 수취 경로 침범 금지).
- **D6 리뷰 루프의 실행 주체**: 분류 후 조치(라이브 진단+패치·park 배치)는
  세션(Claude)이 수행 — 엔진이 자동 패치하지 않는다(제스처 아님 — 정직
  원칙). v1 = 수확+분류만 자동.

## 비-목표

- 저널 UI(앱 화면)·저널 원격 전송·자동 패치 실행(패치는 세션 승인률 유지)
 ·폰 무접속 자동 재시도 루프(원장 계약)·성능 프로파일러 통합.

## 테스트·게이트

- journal: selftest 신설 계보 — append/절단/실패 무시/JSONL 정형 — 캐논 승계
 (신설 어셜션 = 증분·기존 등호).
- harvest: probe 원문(수확 1회 — journal 행 요약+events 원문) 2런.
- 폰 축: 계보 흡수(배포 런 — 접촉 가능 시·미접속=BLOCKED 원장행 원존).
- EYES: 사용자 저널/수확 리포트 모양 체감(나중에).
